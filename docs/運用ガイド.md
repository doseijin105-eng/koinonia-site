# ゲーム制作と公開の運用ガイド(Claude・ChatGPT・Gemini の連携)

第2.1版 2026年11月25日(初版:同日)

前提:ChatGPT と Gemini は有料プランを使っています。

ChatGPT・Gemini・Claude を使い分けて聖書のゲームを作り、公開するための約束ごとです。

## 0. 第2版で変わったこと

- 新しいゲームの作り方を「企画メモ → 小さな試作 → テストプレイ → 仕上げ → 公開」の7段階にしました(3章)
- ChatGPT(Codex)にプルリクエストを確認させる方法(`@codex review`)と、確認してほしい点を `AGENTS.md` に書きました(5章)
- Gemini の絵と音楽を作るときのこつを、新しい機能に合わせて書き直しました(6・7章)
- 子どもにテストプレイしてもらうときの見方と記録表を足しました(8章)
- 公開前チェックリストを、プルリクエストのひな形として GitHub に入れました(9章)
- 本番公開を月4回の「公開日」にまとめ、クレジットが足りなくならないようにしました(10章)
- (2.1)有料プランで使える機能に合わせました:Codex の「クラウド」で GitHub に直接プルリクエストを出す、Gemini の高画質モデル(Nano Banana Pro)、3分までの音楽(5〜7章)

## 1. 基本の考え方

1. **正本は GitHub の koinonia-site ひとつだけ。** ドライブは素材と書類の置き場、ゲームの本体は GitHub です。
2. **小さく作って、早く遊んでもらう。** 全部できてから見せるのではなく、1ステージだけの試作で子どもに遊んでもらいます。
3. **試し公開は無料、本番公開は有料。** 確かめるのは試し公開(デプロイプレビュー)で何回でも。本番は公開日にまとめます。
4. **1回の変更は1つだけ。** 「ステージ追加」と「ボタンの色変更」は別々のプルリクエストにします。確認しやすく、戻しやすくなります。

## 2. 役割分担

| だれ | 主にすること |
|---|---|
| 新井さん | 何を作るか決める。試し公開で遊ぶ。子どもにテストプレイしてもらう。公開の「よし」を出す |
| Claude | 企画メモの相談、素材の組み込み、ChatGPT の変更の確認と取り込み、ランキングなどの共通のしくみ、本番公開と動作確認、仕様メモ・素材管理表の更新 |
| ChatGPT(Codex) | 新しいゲームの試作、機能の追加、プルリクエストの確認(`@codex review`) |
| Gemini | 絵(キャラクター・背景・アイコン・エフェクト)と音楽(BGM・効果音) |

## 3. 新しいゲームを作る手順

1. **企画メモを書く(Claude と相談)。** ひな形は `docs/games/_template.md` です。「ひとことで」「聖書箇所」「伝えたいこと」「遊ぶ人と場面」「1回の長さ」と、**完成の条件**を先に決めます。完成の条件があると、AI が「どこまで作れば終わりか」を取り違えません。
2. **小さな試作を作る(ChatGPT か Claude)。** 絵は仮の図形のままで、遊びの中心だけを1ステージ分作ります。ここで「おもしろいか」を確かめます。
3. **素材を作る(Gemini)。** 遊びが決まってから絵と音楽を作ります。先に作ると、遊びが変わったときにむだになります。
4. **中身を作る。** 試作をもとにステージや画面を増やします。ChatGPT はブランチ+プルリクエストで出します。
5. **試し公開でテストプレイ。** プルリクエストに付く試し公開のURLで、新井さんと子どもに遊んでもらいます(8章)。
6. **仕上げ。** 公開前チェックリスト(9章)を全部確かめます。
7. **本番公開(公開日に Claude が)。** トップページの「あそぶ・まなぶ」にカードを足して公開します。

## 4. いまのゲームを直す手順

1. 直したいことを1つに絞って、ChatGPT か Claude に頼む
2. 試し公開のURLで確かめる
3. よければ Claude に「取り込んで」と伝える(本番に出るのは次の公開日)

急ぎの直し(聖書の表記の間違い、遊べなくなる不具合)だけは、公開日を待たずに公開します。

## 5. ChatGPT(Codex)の使い方

### はじめの準備(1回だけ)

有料プランには Codex が入っています。https://chatgpt.com/codex を開き、GitHub アカウントをつないで、koinonia-site の「環境」を作ります。これで、ChatGPT が自分でリポジトリを読み、ブランチを作り、プルリクエストまで出せるようになります(ファイルを手でやりとりする必要はありません)。GitHub をつなぐ操作は新井さんご自身でお願いします。

### 頼み方の例

```
GitHub の doseijin105-eng/koinonia-site を開き、AGENTS.md と typing/README.md を読んでから作業してください。
みことばタイピングクエストに、ヨナ書のステージを1つ追加してください。
聖書は新改訳2017に合わせ、ふりがなを付けてください。
main には直接入れず、ブランチを作ってプルリクエストにしてください。
説明は日本語で、プルリクエストのひな形の確認項目を埋めてください。
```

### こつ

- **むずかしい頼みごとは、先に計画を出してもらう。** 「作る前に、どのファイルをどう変えるか計画を見せて」と頼み、よければ「その計画で進めて」と伝えます。
- **プルリクエストができたら、AI にも確認させる。** プルリクエストのコメント欄に `@codex review` と書くと、Codex が重大な問題に絞って指摘します(先に Codex の設定で、このリポジトリの「コードレビュー」をオンにしておく必要があります)。何を見てほしいかは `AGENTS.md` の「Code Review Rules」に書いてあります。
- **同じ間違いが2回起きたら、`AGENTS.md` にルールを1つ足す。** 長いルールを最初からたくさん書くより、実際に困ったことだけ短く足すほうが効きます。
- **直してほしいところも、プルリクエストのコメントで頼める。** `@codex review` の指摘を読んで「@codex 指摘の1つ目を直して」と書くと、Codex が直して同じプルリクエストを更新します。
- 使える量はプランごとに決まっています。大きな頼みごとは、1回に1つにすると無駄になりません。
- できたプルリクエストのURLを Claude に送れば、確認して取り込みます。

## 6. Gemini で絵を作るこつ

- **キャラクター設定シートを「見本」にする。** 最初に正面・横・後ろの設定シートを作り、以後の絵では毎回それを添付して「この見た目のまま」と書きます。
- **大事な絵は高画質モデルで。** 有料プランでは、作った絵を「Nano Banana Pro」(Pro のモデル)で作り直せます。キャラクター設定シート、タイトル画面、必殺技のカットインなど、見本や目立つ絵はこちらで仕上げます。走りの何コマもある絵は、ふつうのモデルで十分です。1日に作れる枚数には上限があり、上限を超えるとふつうのモデルに切り替わります。
- **見本の絵は何枚も添付できる。** 設定シートに加えて、色やタッチの見本にしたい既存の絵(たとえばヨシェブの絵)も一緒に添付すると、そろいやすくなります。
- **会話で少しずつ直す。** 気に入らないところは作り直さず、同じ会話で「耳をもう少し長く」「背景をシンプルに」と直してもらうほうが、顔や服がぶれません。
- 背景は白(光のエフェクトは黒)の単色、絵の中に文字は入れません(文字はゲーム側でのせます)。
- 既存の作品名・作家名を「○○風に」と入れないでください。
- Gemini で作った絵には、見えない電子透かし(SynthID)が入っています。素材管理表に「Gemini で作成」と書いておきます。
- 各ゲームの素材プロンプト集(ドライブのゲームのフォルダ)をそのまま貼って使えます。

## 7. Gemini で音楽を作るこつ

- 「ツール」→「音楽を作成」を使います。有料プランなので、**Pro のモデル(Lyria 3 Pro)で約3分まで**作れます(無料は30秒まで)。1日に作れる曲数には上限があります。音楽の生成は18歳以上が対象です。
- **BGM は1〜2分で作る。** 30秒の曲はくり返しが目立つので、1〜2分にすると何度流れても飽きにくくなります。ただしファイルが大きくなるので、ゲームに入れるときは Claude が 96kbps 程度に縮めます。
- Pro のモデルは曲の組み立てを指定できます。BGM なら「イントロなし、同じ雰囲気のままAとBをくり返す」、ジングルなら「5秒で、最後の音ではっきり終わる」のように書きます。
- ゲームの BGM は「歌なし(インストゥルメンタル)」を選び、「ループできるように、始まりと終わりを同じ雰囲気に」と書きます。
- ジャンル、テンポ(例:テンポ130)、楽器、場面の気持ちを入れると、思った曲に近づきます。作曲家やアーティストの名前は入れません。
- MP3 でダウンロードし、素材管理表のファイル名で保存します。

## 8. 子どもにテストプレイしてもらう

最初の数分がいちばん大事です。子どもはすぐに「うまくいかないところをよける遊び方」を見つけてしまうので、初めて遊ぶ子の様子をよく見ます。

- **教えないで見る。** 迷っていても、すぐには説明しません。「説明しなくても分かるゲーム」にするための観察です。
- **止まったところをメモする。** 手が止まった、きょろきょろした、まちがったボタンを押した、などの場所と理由を書きます。考えて止まるのはよい止まり方、分からなくて止まるのは直すところです。
- **質問は少なく、おしゃべりのように。** 「どこがおもしろかった?」「むずかしかったところある?」くらいで十分です。
- **字が読めない子のこと**も考えて、ボタンは絵と文字の両方にします。
- 乗り気でない日は無理をせず、別の日にします。
- 記録は仕様メモの「テストプレイの記録」の表に書きます(名前は書かず、学年くらいだけ)。写真や動画は撮りません。

試し公開の画面の下にある Netlify の道具(Netlify Drawer)を使うと、画面にしるしを付けたコメントがプルリクエストに届きます(新井さんの Netlify へのログインが必要です)。

## 9. 公開前チェックリスト

プルリクエストを作ると、このチェックリストが自動で入ります(`.github/pull_request_template.md`)。

- 試し公開で、最初から最後まで遊んだ
- スマホの幅でも表示がくずれない
- 新しい文字にふりがなを付けた
- 聖書は新改訳2017の表記で、本文を出す画面に「聖書 新改訳2017©2017新日本聖書刊行会」がある
- 秘密(パスワード・キー)や個人情報を入れていない
- 仕様メモを直した

## 10. 公開日とクレジット

- Netlify の無料プランは月300クレジット、本番公開1回で15クレジットです。試し公開(デプロイプレビュー)は無料で何回でもできます。
- **本番公開は「公開日」にまとめます。** 目安は月4回(毎週土曜の夜)。1か月の本番公開は60クレジット、ランキングの動く分を入れても余裕があります。
- 公開日までに取り込んだ変更は、まとめて1回で公開します。
- 説明書(`.md`)、`docs/`、`.github/` だけを直したときは、公開しない設定にしてあります。
- 使い切ると次の月(毎月5日)まで本番公開が止まります。サイトそのものは動き続けます。どうしても急ぐときは、追加のクレジットを買う方法もあります(料金と条件は Netlify の料金ページで確かめてください)。
